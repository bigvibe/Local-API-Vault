# Security Model（初稿）

## 保护目标

本项目旨在保护静态存储的 API 密钥，降低以下风险：

- Vault 文件被复制、备份到其他介质或被他人离线读取
- 配置目录泄露
- 常见应用日志或错误信息意外包含密钥

## 不在保护范围内

以下情况不能仅靠本地 Vault 解决：

- 恶意软件、键盘记录器或屏幕录制
- 已解锁的操作系统账户
- 已被攻破的构建环境或被篡改的依赖
- 用户主动把密钥提交到 Git、粘贴到不安全网页或写入明文 `.env`
- 恶意或不可信的导入文件

## 设计原则

1. 默认不发起网络请求，不包含遥测。
2. 使用经过审查的 `age` 格式和 scrypt 密码派生，不自行设计密码学。
3. 新 Vault 使用 X25519 主文件 + scrypt 加密的身份 sidecar；不把 passphrase 和公钥 recipient 混在同一个 age 文件中。
4. 加密文件写入采用临时文件和替换策略，避免半写入文件。
5. 密钥默认掩码显示，用户必须主动显示或复制。
6. 错误信息不包含密钥、密码或完整 Vault 内容。
7. 解锁状态只保存在进程内存中；锁定时尽力清零敏感数据。
8. 默认保持解锁会话，用户可以随时手动锁定；应用进程退出后会清零并要求重新解锁，不做复杂的自动租约和后台权限系统。
9. 停用只阻止新的读取请求，不能撤销已经被客户端缓存的密钥。
10. Windows Named Pipe 只允许创建者和 SYSTEM 访问，客户端仍受 Vault 解锁状态和条目启用状态约束。
11. 运行配置只保存密钥名称和命令，不保存密钥值。
12. 开机自启动只在当前用户注册表写入启动项，且只负责启动进程；它不会自动解锁，也不预取任何密钥。
13. “复制参考资料”由程序自动遮蔽凭据，用户不需要判断什么算敏感；遮蔽以宁可多遮为准。
14. 导出和导入功能必须明确区分加密数据与明文数据。
