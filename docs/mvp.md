# MVP 验收标准

## 主流程

1. 首次启动显示默认 Vault 路径。
2. 用户可以用至少 12 个字符的主密码创建 Vault。
3. 忘记密码时，重建流程会保留旧文件并创建空 Vault。
4. Vault 文件中不出现明文密钥。
5. 用户重新打开 Vault 时可以解锁。
6. 用户可以添加、编辑、删除、停用/启用和搜索条目。
7. 停用条目保留在 Vault 中，但普通读取接口和 CLI 拒绝返回。
8. 条目默认掩码显示，主动显示或复制后才提供明文。
9. 复制后 30 秒尝试清空剪贴板。
10. 解锁后默认可以持续使用，用户可以随时手动锁定。
11. `.env` 文件可以导入为环境变量条目。
12. 可以使用原生文件选择器选择 Vault 和 `.env` 文件。
13. 可以导出仍然保持加密的 Vault 备份。
14. 可以验证当前主密码并安全修改主密码。
15. 可以生成、保存并使用恢复身份文件恢复 Vault。
16. CLI 可以在不把主密码放入参数的情况下读取条目。
17. CLI 可以通过 Named Pipe 注入环境变量并启动本地命令。
18. 应用内可以保存运行配置，并通过 `run <profile>` 启动。
19. 可选开机自启动：登录后静默进入托盘并保持锁定，可从侧边栏或托盘菜单切换。

## 非目标

- 云端同步
- 账户和团队权限
- 浏览器插件
- 复杂 IDE/Docker 编排
- 对抗系统级恶意软件
- 独立安全审计结论

## 完成 MVP 后

- 增加恢复身份轮换和撤销
- 增加加密备份恢复向导
- 设计 CLI 的项目/环境注入命令
- 进行第三方安全审查和发布签名
