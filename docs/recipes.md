# Recipes：如何在真实项目里用起来

> 这份文档只覆盖**当前版本真实能做到的事**。写不了的地方直接说"不支持"，不猜。
> 没看到你的场景 = 先当作不支持，别硬凑。

## 环境变量消费型项目（主流场景）

项目能读 `%VAR%` / `os.environ` / `process.env` —— 把密钥注入进程环境即可，
文件里永远没有明文。

```powershell
# 注入单条命令
lvault run -- python bot.py

# 通过 Run Profile（名称自选，例如 newsfeed-prod）
lvault run newsfeed-prod
```

Profile 里只存「命令 + 所需条目名」，**不含密钥值**。

### Node 项目

```powershell
lvault run -- npm run start
```

### Python 项目

```powershell
lvault run -- python manage.py scrape
```

### Windows 内置命令

```powershell
lvault run -- cmd /c "some-tool --check"
```

## 每个项目只配置一次：`.lvault.toml`

如果每次都列 `--secret` 很烦，在项目根目录放一个 `.lvault.toml`：

```toml
vars = ["NEWSFEED_API_KEY", "OAK_PRIVATE_JWT"]
```

- 里面**只有名字，没有值**，可以放心提交进仓库，和代码一起走
- 在这个目录下直接运行即可，不必再写 `--secret`：

  ```powershell
  lvault run -- python bot.py
  ```

- 只认**当前目录**的 `.lvault.toml`，不会往父目录找
- 同时写了 `--secret` 时，以命令行为准

这和 Run Profile 的区别：`.lvault.toml` 跟着仓库走（适合多人/多机克隆同一项目），
Run Profile 存在本机应用里（适合完全不进仓库的临时命令）。两者都只存名字，不存值。

## 项目读「配置文件」怎么办

这个工具**不会**生成 `.env` 文件，也**不会**让别的工具去接收一整份密钥。
如果你的项目要求一个配置文件里有明文，只有三条路：

1. **改配置读法**（推荐）：大多数配置库支持环境变量插值，例如
   `api_key = "${NEWSFEED_API_KEY}"`，然后用 `lvault run` 注入。
2. **项目改读环境变量**（最好）：不需要配置文件里有密钥。
3. 拒绝明文进磁盘：如果以上两条都走不通，这个项目**不适合**用本工具管理，
   请改用别的秘密管理方案（见"不适合"）。

## 我要在另一台电脑上用同样的密钥

做不到（也不该做）：**本工具不提供同步、没有账号系统、没有云端副本。**

正确做法是每台机器各建一份 Vault，各自导入 `.env`（或手动添加）。
备份用「导出加密备份」，换机器时导入即可——备份本身也是加密的。

## 我要把密钥分享给同事

做不到：没有共享/协作模式，没有权限分级，没有团队账号。
这是明确的设计边界。请用共享密钥管理器（例如 1Password Teams / Vaultwarden / 云 KMS）。

## CI/CD 场景

**不支持**：CI 运行环境没有「本机用户」这一层解锁上下文，
Named Pipe 的 ACL（当前用户 + SYSTEM）对 CI agent 是开的，但 CI 上没有人输主密码，
Vault 会永远处于锁定状态；更重要的是 `lvault` 是交互式解锁设计，
**没有**非交互解锁 API（刻意为之——避免主密码出现在脚本里）。

CI 上请用平台的 secret store（GitHub Actions Secrets / GitLab CI Variables 等）。

## 项目只认"把密钥写进文件"怎么办

这个工具做不到，也不做：**不会替你创建含密钥的明文文件**。
如果你的工具只接受明文文件，你需要：

1. 先把工具改写成读环境变量（推荐，治本）；
2. 或者接受该项目**不适合**本工具管理，改用环境注入或其它方案。

## 怎么确认我的 Vault 还是好的

跑一次只读体检：

```powershell
lvault verify
```

它会检查 Vault 文件在不在、格式对不对、口令 sidecar 在不在，
**不索要主密码、不需要应用在运行、也不会打印任何密钥值**。

- 退出码 `0` = 没发现问题，`1` = 有失败项
- 想知道「恢复身份到底还能不能打开这个 Vault」，加 `--identity`：

  ```powershell
  lvault verify --identity D:\backup\recovery.key
  ```

- 老 Vault（口令格式，没有恢复身份）会被标成「注意」：那说明你忘了主密码只能重建空 Vault，
  可以考虑在应用里「设置恢复密钥」升级成身份格式

什么情况下值得跑：换过机器、做过系统还原、备份过 Vault、或者只是想确认文件没坏。

## 谁读过我的密钥

```powershell
lvault audit
```

或者在应用侧边栏点**「读取记录」**，看的是同一份记录。

每条记录写着：什么时候、**哪个进程**（服务端核实的进程名与 PID）、读了哪个**条目名**、结果。

```text
2026-11-12 10:30:15  local-api-vault-cli.exe (PID 12345)  NEWSFEED_API_KEY  ok  D:\projects\web
2026-11-12 10:31:02  node.exe (PID 20984)  NEWSFEED_API_KEY  ok  D:\projects\web
```

心里要有数：

- 进程与 PID 是**服务端核实**的（从管道句柄问内核要），改不了
- 项目和工作目录是**调用方自己说的**，只能当线索
- 管道只允许当前用户和 SYSTEM，所以它回答的是「哪个进程」，不是「哪个人」——
  同一个账户下的任何程序都能拿走密钥。这是事后追查，不是防护
- 记录只在内存里，重启应用就没了；里面有条目名，没有密钥值

## 忘主密码了怎么办

首屏点**「恢复 Vault」**，向导分三步：

1. 选回**原来那个** Vault 文件（默认路径已经填好）
2. 选出创建时保存的**恢复身份文件**（内容是一行 `AGE-SECRET-KEY-1…`）
3. 设一个**新的主密码**（至少 12 个字符），旧主密码立刻失效

恢复完成后弹窗会交代三件事：条目都在、恢复身份文件**依然有效**（继续保存好）、建议重新导出一次加密备份。

分清两个按钮：

| 按钮 | 做什么 | 数据 |
|---|---|---|
| 恢复 Vault | 用恢复身份打开原 Vault | 原来的条目都在 |
| 重建 Vault | 创建空的新 Vault | 原文件保留成 `vault.age.before-rebuild-…`，旧密码仍能打开它 |

**没有恢复身份文件就只剩重建这一条路**：主密码本身没有任何找回途径。这也是为什么创建 Vault 时给的那份恢复身份文件必须离线保存好。

## 我的备份怎么用回来

侧栏**「从备份恢复」**，三步：

1. 选回你导出的那份备份（`vault.age`）
2. 输入这把 Vault **原来的主密码** → 点「校验备份」，会告诉你里面有几个条目
3. 点「恢复」：当前 Vault 被备份内容替换，**恢复前的 Vault 保留在旁边**（文件名带 `.before-restore-…`）

几个容易踩的点：

- 备份是**一对**文件：`vault.age` 和旁边的 `vault.identity.age`，得在同一个目录里
- 校验只报数量，不报条目名和值
- 恢复**沿用备份原来的身份**，所以你的恢复密钥文件照样能打开恢复后的 Vault
- 恢复用的还是备份原来的主密码。如果这份备份的主密码曾经泄露过，恢复完记得去侧栏「修改主密码」换一把

## 我怀疑恢复密钥泄露了

侧栏**「更换恢复密钥」**：

- 换发之后，**旧的那把恢复密钥立刻失效** —— 它再也打不开这个 Vault
- 新的这把要保存好，旧的可以销毁
- 换发前的 Vault 保留在旁边（`vault.before-rotate-…`），还是旧密钥能打开的旧数据，不会丢

怎么知道某个恢复密钥还在不在？

```powershell
lvault verify --identity D:\backup\recovery.key
```

打不开就说明它已经失效了（被换发过，或者对不上这个 Vault）。

## 密码轮换怎么办

**不支持自动轮换**：本工具没有后台任务、没有静默续期、不会主动连任何服务商。

轮换流程是手动的：

1. 在服务商后台生成新 Key
2. 在 Vault 里替换条目值（编辑保存）
3. 确认注入的项目用上新值（下次 `lvault run` 生效）
4. 旧 Key 在服务商侧撤销

## ".env 导入"到底导入了什么

**不过滤任何键值**——包括路径、开关等看似"不像密钥"的值。这是**刻意设计**：
保险箱宁可多存，不可漏存。导入后可在列表里逐个删除不需要的条目。

## 一次性 / 临时场景

```powershell
# 临时拿一个值用于一次性调试（不要重定向到日志、不要粘贴到对话）
lvault get NEWSFEED_API_KEY
```

退出 30 秒后剪贴板会被自动清空（仅在通过界面复制按钮时生效）。
`get` 输出直接打到 stdout，**任何**关于"本次调试"的日志里都不该出现它。

## 不适合用本工具的情况速查

| 你的需求 | 结论 |
|---|---|
| 多台机器密钥同步 | 不支持，每台各自建 Vault + 加密备份导入 |
| 团队共享密钥 | 不支持，用团队密钥管理器 |
| 自动轮换 / 续期 | 不支持，必须手动三步 |
| CI 注入密钥 | 不支持，用 CI 平台的 secret store |
| 把密钥写成配置文件给别的软件读 | 不支持（明文落盘），改用环境变量插值 |
| 跨操作系统（macOS/Linux） | 当前仅 Windows |
| 需要"主密码忘了找回" | 只能用恢复身份文件，没有后门、没有找回 |
| 加密密钥文件+整个仓库推远端 | 不做，本地文件含明文风险 |
